# AI 大模型应用项目 · 8 周学习 + 求职路线图

> 面向对象：具备传统 Java 后端开发经验、想补齐「AI 大模型项目经验」的求职者
> 目标产出：8 周内做出一个能写进简历、经得起面试追问的 **RAG + Agent** 项目
> 核心原则：不追算法、不训模型；用 Java 生态做 AI 应用，把你的后端工程经验变成差异化优势

---

## 0. 先读这段：定位与核心策略

招聘 JD 里写的「有 AI 大模型项目经验」，绝大多数指的是**应用层工程能力**，不是算法研究能力。RAG、Agent 本质是「检索 + 编排 + 调工具」的软件工程问题，正好落在你已有的舒适区里（接口设计、数据库、并发、部署、稳定性）。

你的差异化定位应该是：

- **语言**：全程 Java，简历上打「Java + 大模型应用」，比满屏 Python 更少见、更好讲。
- **不做的**：自己训练/微调模型、啃注意力机制论文、纠结向量库选型到细节。
- **要做的**：把 LLM 当成一个「能力接口」，用工程手段做出**可用、可评测、可部署**的产品。

### 贯穿全程的项目设定

只做一个项目，让它一路长大，覆盖所有招聘关键词：

> **「企业知识库智能助手」** —— 员工可以自然语言提问，助手基于公司文档作答并给出引用来源（RAG），还能调用内部工具查订单、查库存、做多步任务（Agent）。

一鱼多吃：一份项目同时覆盖 RAG、向量检索、Agent、Function Calling、Prompt 工程、评测、部署。

## 3. 8 周路线图

每周统一结构：**目标 → 学习重点 → 动手交付 → 验收标准 → 简历话术**。

### 第 1 周：打好地基 + 跑通最小 RAG 闭环

**目标**：理解 LLM 应用的基本形态，跑通「文本 → 模型 → 回答」。

**学习重点**
- LLM API 调用（OpenAI 兼容接口）、消息角色 `system / user / assistant`
- Prompt 基础、让模型输出结构化 JSON
- Token、上下文窗口、费用概念
- Spring AI 核心抽象 `ChatClient`

**动手交付**
- 新建 Spring Boot 项目，加入 Spring AI 依赖
- 一个 `/chat` 接口，能对话
- 最小 RAG：读取一段本地文本 → embedding → 存内存向量库 → 检索 → 生成

**验收标准**：问知识库里有的内容，能答对；问库里没有的，能承认不知道。

**简历话术**：从 0 搭建 Spring AI 工程骨架，实现大模型对话接口与最小 RAG 检索链路。

---

### 第 2 周：文档解析与分块（Chunking）策略

**目标**：让系统能吃真实文档，而不是手写的一段文本。

**学习重点**
- PDF / Word / Markdown 解析（Tika、PDFBox）
- 分块策略：固定长度、按标题层级、重叠窗口
- Embedding 模型选择与批量处理

**动手交付**
- 文档上传接口
- 文档解析器 + 可配置分块器
- 索引服务：把分块写入向量库

**验收标准**：支持至少 PDF + Word + Markdown；能用不同分块参数做对比。

**简历话术**：实现多格式文档解析管线与可配置分块策略，支撑知识库自动索引。

---

### 第 3 周：向量检索工程化 + 引用溯源 + 多轮对话

**目标**：从「玩具」变成「工程」，答案可追溯、对话有记忆。

**学习重点**
- 向量库选型与持久化（pgvector）
- 相似度、top-k、元数据过滤
- 多轮对话记忆（会话上下文）
- 引用溯源（答案标注来源文档/段落）

**动手交付**
- 持久化向量库（替换内存实现）
- 检索结果带来源，生成答案时附带引用
- 会话记忆 + 引用在返回结构里呈现

**验收标准**：答案能标注「来自第 X 个文档第 Y 段」，幻觉明显下降。

**简历话术**：基于 pgvector 实现持久化向量检索与引用溯源，答案可追溯到原文段落，显著降低幻觉。

---

### 第 4 周：RAG 评测与优化（拉开差距的一周）

**目标**：能**量化**地证明你的 RAG 好不好，并优化它。

**学习重点**
- 构建评测集（真实问题 + 标准答案/标准片段）
- 指标：召回命中率、答案准确率
- Rerank（重排）、混合检索（关键词 BM25 + 向量）

**动手交付**
- 20–50 条问题的评测集
- 评测脚本/指标输出
- 引入 rerank + 混合检索
- 一份「优化前 vs 优化后」报告

**验收标准**：至少一项指标有可量化的提升（例如命中率 62% → 87%）。

**简历话术**：搭建 RAG 评测集并引入 rerank 与混合检索，检索命中率从 X% 提升到 Y%。

---

### 第 5 周：Agent 基础 —— Function Calling / Tool Use

**目标**：让助手能「动手」——调用你自己的 Java 方法。

**学习重点**
- tool / function schema 定义
- 模型如何决定调用哪个工具、参数怎么传
- 工具执行结果如何回灌给模型
- 一轮对话内的多次工具调用

**动手交付**
- 2–3 个 Java 工具（查订单、查库存、算价格、查时间等）
- Agent 编排循环：判断是否需要调工具 → 调用 → 回灌 → 生成

**验收标准**：问「订单 A1001 能不能退」，能自动调用查订单工具并给出条件判断结论。

**简历话术**：基于 Function Calling 实现工具调用，让助手可查询订单/库存等内部系统。

---

### 第 6 周：Agent 进阶 —— 多步规划与健壮性

**目标**：从「调一个工具」升级为「完成多步任务」，并处理出错。

**学习重点**
- 多步任务规划（ReAct 式：思考 → 行动 → 观察 → 再思考）
- 工具选择错误、参数错误、超时、重试与兜底
- 权限与安全边界（哪些工具可被调用）

**动手交付**
- 支持多步任务的 Agent
- 工具失败兜底 + 重试机制
- 简单的 planner / 决策逻辑

**验收标准**：一个需要多次工具调用的复杂任务能完成；工具失败时有合理兜底。

**简历话术**：实现多步任务规划与工具编排，支持失败重试、结果校验与调用权限控制。

---

### 第 7 周：产品化 —— 前端 + 流式输出 + 部署 + 可观测

**目标**：让项目「像个产品」，能演示、能部署、能讲成本。

**学习重点**
- SSE 流式输出（打字机效果）
- Docker / Docker Compose 部署
- 日志、追踪、token 用量与成本统计

**动手交付**
- 一个可用的对话前端
- SSE 流式响应
- Docker Compose 一键启动
- token 统计 / 简单调用追踪

**验收标准**：一条命令拉起全部服务，能现场演示流式对话。

**简历话术**：实现 SSE 流式响应与容器化部署，加入对话追踪与 token 成本统计。

## 5. 面试高频问题与答题要点

1. **为什么要切分文档？怎么切？**
   答：上下文窗口有限、检索粒度要匹配问题；策略有固定长度、按标题层级、重叠窗口，需按文档结构选择并做对比实验。

2. **检索召回不准怎么办？**
   答：优化分块、换 embedding 模型、加 rerank、混合检索（关键词+向量）、元数据过滤、扩大 top-k 再重排。

3. **怎么防止/减少幻觉？**
   答：只让模型基于检索到的上下文作答、要求给出引用、无依据时明确说不知道、可加答案校验。

4. **RAG 和微调怎么选？**
   答：知识频繁更新、需溯源用 RAG；固定风格/格式或领域术语用微调；多数应用场景 RAG 性价比更高。

5. **Agent 为什么会调错工具？怎么解决？**
   答：工具描述不清、工具太多、Prompt 不明确；解法是写清工具用途与参数、限制可选工具、加校验与兜底重试。

6. **怎么控制 token 成本？**
   答：精简上下文、控制检索条数、缓存、按需裁剪历史、监控用量与费用。

7. **怎么评测你的 RAG？**
   答：建真实问题评测集，测召回命中率与答案准确率，做优化前后对比。

8. **你的项目有什么难点？**
   准备好 1–2 个真实踩坑故事（如分块过大导致召回差、rerank 接入后延迟上升等）和你的解决过程。

## 6. 避坑清单（很重要）

- ❌ 一上来就想训模型/微调 —— 不是应用岗要的，浪费几周。
- ❌ 工具选型反复纠结 —— 先用 Spring AI + pgvector 跑通，别在选型上停摆。
- ❌ 做一堆玩具 demo —— 一个贯穿项目胜过五个半成品。
- ❌ 只写代码不写评测 —— 没有数字，面试无法证明「你做的有效」。
- ❌ 只做后端不做演示 —— 要有能看的界面和 Demo 视频。
- ❌ 项目做完不会讲 —— 第 8 周专门练「3 分钟讲清楚」。

## 7. 每周节奏与时间管理

- **每周投入建议**：业余 10–14 小时（工作日晚上 1–1.5h + 周末各 4h）。
- **每周固定节奏**：周一~周三学 + 写代码，周四把本周功能跑通，周五写小结，周末做验收和补文档。
- **每周留一份产出**：即使进度慢，也保证每周有一件能写进简历的实物。
- **卡住超过 2 小时**就跳过、记录问题，先把主线跑通，回头再补。
