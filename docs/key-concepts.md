# 关键概念速查

> 这个项目里那些「会被追问」的概念，一句话讲清。

1. **分块**：为什么不能把整篇文档直接塞给模型？（`SimpleTextSplitter`）
2. **向量化**：`IngestionService` 把文本片段交给 `EmbeddingModel` 转成向量。
3. **检索**：`RagService` 用 `similaritySearch` 按语义找最相关的 `topK` 个片段。
4. **生成**：把检索结果拼成上下文，连同「只依据资料作答」的系统提示一起发给模型。
5. **解析**：真实文档格式各异，先把它们统一成纯文本（`TikaDocumentParser`），再谈分块。
6. **分块策略**：固定长度简单但会切断语义；按标题/段落切更贴合文档结构，但依赖文档质量。
7. **批量 embedding**：`IngestionService` 一次性把片段列表交给向量库，减少接口调用次数。
8. **向量库抽象**：上层只依赖 `VectorStore` 接口，内存与 pgvector 靠配置切换，换实现不动业务代码。
9. **引用溯源**：给片段编号并把来源写进提示词，模型才能在答案里标注 `[1]`；返回结构再把编号映射回原文位置。
10. **元数据过滤**：`source` 既可以用来限定检索范围，也可以用来「先删后写」实现重复导入去重。
11. **会话记忆窗口**：只保留最近 N 条消息，既让模型记住上下文，又不让历史把 token 撑爆。
12. **Function Calling / Tool Use**：模型不直接访问数据库，它只提出「我要调哪个函数、参数是什么」，由你的代码执行。
13. **工具描述就是 Prompt**：`@Tool` 的 description 与 `ToolParam` 决定模型调不调、怎么填参，写不清楚模型就会调错。
14. **编排循环**：请求工具 → 执行 → 回灌结果 → 再判断，循环到模型给出最终答复；Spring AI 的 `ChatClient` 内部完成这一步。
15. **工具只给事实**：业务工具返回订单事实、知识工具返回政策原文，让模型去组合结论，工具本身保持通用。
16. **RAG 也是工具**：把检索包成 `searchKnowledgeBase` 之后，「查资料」和「查订单」在模型眼里是同一种能力。
17. **可观测性**：`RecordingToolCallback` + `ToolCallRecorder` 让每次工具调用可见，既能演示也能写断言。
18. **任务规划**：复杂问题先用规则拆成有序步骤（`AgentPlanner`），把「先查什么、后查什么」讲清楚，而不是全交给模型临场发挥。
19. **最小权限**：只把计划内的工具交给模型（`callbacksFor`），模型看不到本轮用不到的工具，也就调不错。
20. **超时与重试**：慢依赖放在独立线程上设超时，失败后指数退避重试，避免一个偶发错误放大成整轮失败。
21. **失败兜底**：重试耗尽后返回结构化提示而不是抛异常，让模型基于已有信息作答并如实说明缺口（`degraded`）。
22. **流式输出**：模型可以边生成边返回（`ChatClient.stream()`），前端逐片追加就是打字机效果，体感远好于「憋完整段」。
23. **SSE 的错误边界**：开始推流后状态码必然是 200，之后的失败只能作为事件下发；未开始的失败仍走 HTTP 语义。
24. **客户端断开要清理**：`AbortController` 断开连接后，后端要 `dispose` 上游订阅，否则模型还在烧钱。
25. **跨线程的上下文**：流式下工具跑在 Reactor 线程上，`ThreadLocal` 会失效，改用 `ToolContext` 携带本轮会话 ID。
26. **成本可见**：记录模型名与 token 用量，按单价估算费用并按入口/模型汇总，「花了多少」从猜测变成数据。
27. **可部署性**：Dockerfile 两阶段构建 + Compose 编排，一条命令起全套；镜像只装运行需要的东西。
28. **超时要自己设**：框架默认的重试次数与退避可能长到让用户以为「卡死」（Spring AI 默认 10 次、最长 3 分钟），
    必须显式收敛重试并给 HTTP 客户端加连接/读取超时，失败才能尽快变成一条可读的错误。
29. **持久化要端到端**：向量落库只解决一半问题，内存态的关键词索引也得在启动时重建，否则重启后检索效果会静默变差。
30. **界面的等待要有出口**：耗时操作要显示「等了多久」并提供取消，超时后说清「后端可能仍在处理」，而不是白屏式转圈。
31. **量化要先讲口径**：`Precision@K` 是 0.25 不是因为检索差，而是「每题只标 1 个正确片段、`topK=4`」的理论上限；
    先说口径、再说数字，比被追问时才解释可信得多。
32. **文档要能讲出来**：写文档的目的不是「文件更全」，而是让你**能把它讲清楚**。
33. **边界就是判断力**：主动说清「26 条评测集、用量只在内存、没做鉴权」，
    比把项目吹成什么都能干更让人信服。
